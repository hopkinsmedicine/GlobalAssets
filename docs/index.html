User Guide — Consuming Global Assets

For web authors, site builders, and application teams embedding shared JavaScript and CSS libraries from the Johns Hopkins Medicine CDN.

1. Searching & Filtering Libraries

The Global Assets Portal provides instant access to approved JavaScript and CSS libraries hosted on Azure Blob Storage.

  • Instant Search: Click the search bar (or press / on your keyboard) and type a library name, version number, or filename — for example, jquery 5.3 or font-awesome.
  • Category Filter Tabs: Use the filter tabs beneath the search bar to switch between All Assets, JavaScript (/js/cdn/), or Stylesheets (/css/cdn/).

2. Selecting Library Versions

Each library card groups all available versions of that asset together so you can easily target a specific release.

  • Use the Version dropdown in the top-right corner of any library card to filter that card to a specific version (e.g., v5.3 (Latest) or v4.1).
  • Select All Versions to compare all hosted versions side by side.

3. Copying URLs & HTML Snippets

Every file row offers three quick actions on the right side:

Copy URL

Copies the raw direct HTTPS link to the file on the JHM Azure CDN (useful for module loaders, CMS fields, or dynamic script loaders).

Copy <script> / <link>

Copies a complete, ready-to-paste HTML tag formatted automatically for either JavaScript or CSS.

Open Raw File

Opens the asset directly in a new browser tab so you can inspect the file contents or verify version headers.

4. Embedding Assets in Your Web Pages

Paste CSS <link> tags inside your document's <head>, and JavaScript <script> tags either in <head> or right before the closing </body> tag:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>JHM Web Application</title>

  <!-- Font Awesome Stylesheet from JHM Global Assets CDN -->
  <link rel="stylesheet" href="https://jhmcdn.blob.core.windows.net/global-assets/css/cdn/font-awesome/5.3/all.min.css">
</head>
<body>

  <!-- jQuery Script from JHM Global Assets CDN -->
  <script src="https://jhmcdn.blob.core.windows.net/global-assets/js/cdn/jquery/5.3/jquery.min.js"></script>
</body>
</html>

Developer Guide — Maintaining & Extending the Repository

For engineers managing the Global Assets codebase, adding new libraries or versions, testing locally, and deploying to Azure Blob Storage.

1. Directory Structure & Separation of Concerns

To strictly separate the Portal UI files from the Hosted CDN Libraries, the repository enforces a clean /cdn/ subfolder boundary:

/
├── index.html                                    # Main Global Assets Portal UI
├── docs/
│   └── index.html                                # User & Developer Documentation (this page)
├── img/
│   ├── favicon.ico                               # Browser tab favicon
│   └── logo.png                                  # Johns Hopkins Medicine official logo
├── css/
│   ├── site.css                                  # Stylesheet for the Portal UI & Docs ONLY
│   └── cdn/                                      # <-- Hosted CSS CDN Libraries live here
│       └── font-awesome/
│           ├── 4.1/
│           │   └── font-awesome.min.css
│           └── 5.3/
│               └── all.min.css
└── js/
    ├── site.js                                   # Dynamic discovery, search & copy logic for the UI
    └── cdn/                                      # <-- Hosted JS CDN Libraries live here
        └── jquery/
            ├── 4.1/
            │   └── jquery.min.js
            └── 5.3/
                └── jquery.min.js

Why this matters: The discovery engine in /js/site.js specifically scans paths matching ^(css|js)/cdn/{library}/{version}/{file}$. Portal files like /css/site.css, /js/site.js, and /docs/index.html are automatically excluded from the CDN catalog!

2. Adding a New Library or Version (Zero Code Changes!)

You do not need to edit any HTML or JavaScript to add a new library or version to the UI. Simply follow the folder naming convention:

  1. For a JavaScript library: Create a folder at /js/cdn/{library-slug}/{version}/ and place your .js file(s) inside.
    Example: /js/cdn/bootstrap/5.3.2/bootstrap.bundle.min.js
  2. For a CSS library: Create a folder at /css/cdn/{library-slug}/{version}/ and place your .css file(s) inside.
    Example: /css/cdn/bootstrap/5.3.2/bootstrap.min.css
  3. Upload to Azure Blob Storage: Upload the new folder into the global-assets container. The moment it is uploaded, clicking Sync (or refreshing index.html) will automatically list the library, group its versions, and generate its copy buttons!

3. Local Development Workflow

When working locally on your machine, the portal supports automatic local folder discovery:

  • Recommended (VS Code Live Server / Local HTTP Server): Run a local development server (such as the VS Code Live Server extension, npx serve, or python -m http.server). When running on localhost or 127.0.0.1, /js/site.js automatically crawls your local /css/cdn/ and /js/cdn/ directory listings. Drop a file in locally, hit refresh, and it appears immediately!
  • Source Switcher in the UI: Use the Source dropdown in the top toolbar to switch between:
    • Auto (Smart Detect) — Uses local folders on localhost, or Azure Live XML in production.
    • Azure Blob Live XML — Forces the UI (even on localhost) to query the live Azure container at jhmcdn.blob.core.windows.net.
    • Local /cdn/ Folders — Forces the UI to crawl local directories.

4. Azure Blob Storage & CORS Configuration

For live Azure auto-discovery and cross-domain asset loading to work, the Azure Storage Account (jhmcdn) and container (global-assets) are configured as follows:

  • Container Public Access Level: Set the global-assets container access level to Container (anonymous read access for containers and blobs). This enables the public XML listing endpoint:
    https://jhmcdn.blob.core.windows.net/global-assets?restype=container&comp=list
  • Resource Sharing (CORS): Under the jhmcdn Storage Account → Settings → Resource sharing (CORS) → Blob service:
    • Allowed origins: *
    • Allowed methods: GET, HEAD, OPTIONS
    • Allowed headers / Exposed headers: *
    • Max age: 86400

5. How the 3-Tier Discovery Engine Works (/js/site.js)

Under the hood, /js/site.js uses a resilient 3-tier discovery pipeline:

  1. Tier 1 — Azure Blob Live XML: Fetches ?restype=container&comp=list (with automatic <NextMarker> pagination support for large containers), parses each <Blob> node, extracts file size and last-modified date, and filters for ^(css|js)/cdn/ paths.
  2. Tier 2 — Local Dev Server Crawler: Recursively crawls directory links inside /css/cdn/ and /js/cdn/ when running on a local dev server.
  3. Tier 3 — Offline Fallback Preview: Provides a built-in fallback preview if opened directly via file:// without network connectivity.

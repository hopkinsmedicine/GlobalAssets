User Guide — Consuming Global Assets

For web authors, site builders, and application teams embedding shared JavaScript, CSS stylesheets, and official images from the Johns Hopkins Medicine CDN.

1. Searching & Filtering Assets

The Global Assets Portal provides instant access to approved JavaScript, CSS, and image assets hosted on Azure Blob Storage.

  • Instant Search: Click the search bar (or press / on your keyboard) and type a library name, image category, predefined alt text, version number, or filename — for example, bootstrap, font-awesome, or jhm-logo.
  • Category Filter Tabs: Use the filter tabs beneath the search bar to switch between All Assets, JavaScript (/js/cdn/), Stylesheets (/css/cdn/), or Images (/img/cdn/).

2. Selecting Library Versions

Each library card groups all available versions of that asset together so you can easily target a specific release.

  • Use the Version dropdown in the top-right corner of any library card to filter that card to a specific version (e.g., v5.3.8 (Latest) or v4.7.0).
  • Select All Versions to compare all hosted versions side by side.
  • For flat image category folders (such as /img/cdn/logos/), the version selector is automatically hidden unless versioned subfolders exist.

3. Copying URLs & HTML Snippets

Every file row offers three quick actions on the right side:

Copy URL

Copies the raw direct HTTPS link to the file on the JHM Azure CDN (useful for module loaders, CMS fields, or CSS background images).

Copy <script> / <link> / Generate Tag

Copies a complete, ready-to-paste HTML tag for JS/CSS, or opens the Generate Image HTML Tag modal pre-populated with official metadata.

Open Raw File

Opens the asset directly in a new browser tab so you can inspect the file contents or view the full-resolution image.

4. Generating Image Tags (Predefined Metadata)

Every official image in the Images tab includes pre-approved alt and <figcaption> text defined in the repository's images catalog. Clicking Generate Tag opens the tag generator modal:

  • Format Toggle: Switch between:
    • <img> tag only — Generates a standalone <img src="..." alt="..." loading="lazy"> tag using the predefined alt text.
    • <img> with <figure> and <figcaption> — Wraps the image in semantic <figure> and <figcaption> markup pre-populated with both the predefined alt and figcaption text.
  • Pre-Populated & Ready to Copy: Both the Alt Text and Caption Text (<figcaption>) fields are automatically filled from the predefined images[] array and locked by default to ensure brand and accessibility consistency.
  • Optional Override: If a page requires custom context, click Unlock to Customize to edit the text in real time, or click Reset to Predefined to restore the official values.

5. Embedding Assets in Your Web Pages

Paste CSS <link> tags inside your document's <head>, JavaScript <script> tags in <head> or right before </body>, and generated <img> or <figure> tags directly into your page body:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>JHM Web Application</title>

  <!-- Font Awesome Stylesheet from JHM Global Assets CDN -->
  <link rel="stylesheet" href="https://jhmcdn.blob.core.windows.net/global-assets/css/cdn/font-awesome/6.7.2/all.min.css">
</head>
<body>

  <!-- Generated Image with Predefined Alt & Figcaption from JHM Global Assets CDN -->
  <figure>
    <img src="https://jhmcdn.blob.core.windows.net/global-assets/img/cdn/logos/jhm-logo.png" alt="Johns Hopkins Medicine official horizontal logo" loading="lazy">
    <figcaption>Johns Hopkins Medicine — Official Brand Mark</figcaption>
  </figure>

  <!-- Bootstrap Script from JHM Global Assets CDN -->
  <script src="https://jhmcdn.blob.core.windows.net/global-assets/js/cdn/bootstrap/5.3.8/bootstrap.min.js"></script>
</body>
</html>
Perspective 02

Developer Guide — Maintaining & Extending the Repository

For engineers managing the Global Assets codebase, adding new libraries, versions, or images, maintaining the predefined images[] metadata array, and deploying to Azure Blob Storage.

1. Directory Structure & Separation of Concerns

To strictly separate the Portal UI files from the Hosted CDN Assets, the repository enforces a clean /cdn/ subfolder boundary across /css/, /js/, and /img/:

/
├── index.html                                    # Main Global Assets Portal UI
├── docs/
│   └── index.html                                # User & Developer Documentation (this page)
├── img/
│   ├── favicon.ico                               # Portal browser tab favicon (excluded from CDN)
│   ├── logo.png                                  # Portal header logo (excluded from CDN)
│   └── cdn/                                      # <-- Hosted Image CDN Assets live here
│       └── logos/
│           └── jhm-logo.png
├── css/
│   ├── site.css                                  # Stylesheet for the Portal UI & Docs ONLY
│   └── cdn/                                      # <-- Hosted CSS CDN Libraries live here
│       └── font-awesome/
│           └── 6.7.2/
│               └── all.min.css
└── js/
    ├── site.js                                   # Predefined images[] array + discovery & UI logic
    └── cdn/                                      # <-- Hosted JS CDN Libraries live here
        └── bootstrap/
            └── 5.3.8/
                └── bootstrap.min.js

Why this matters: The discovery engine in /js/site.js specifically scans paths inside /css/cdn/, /js/cdn/, and /img/cdn/. Portal UI files like /img/logo.png, /img/favicon.ico, /css/site.css, /js/site.js, and /docs/index.html are automatically excluded from the CDN catalog!

2. Adding New JS or CSS Libraries / Versions

Because /js/site.js dynamically scans all folders matching /{css|js}/cdn/{library-name}/{version}/{file}, you do not need to make any code changes when adding JS or CSS libraries:

  1. Create the library and version folder inside /js/cdn/ or /css/cdn/:
    /js/cdn/{library-name}/{version}/ or /css/cdn/{library-name}/{version}/
  2. Place your .js or .css file(s) inside that version folder:
    /js/cdn/bootstrap/5.3.8/bootstrap.min.js

3. Adding Images to /img/cdn/ & Updating the images[] Array

Whenever you add a new image into /img/cdn/, follow this 2-step workflow so the image has predefined alt and figcaption metadata:

  1. Step 1 — Add the image file into a category folder under /img/cdn/:
    For example: /img/cdn/logos/jhm-logo.png (if an image ever needs a version number, include it in the filename, e.g., jhm-logo-v2.png).
  2. Step 2 — Add a matching entry to the images array at the top of /js/site.js:
    Open /js/site.js and add an object with source, alt, and figcaption to the images array right at the top of the file: 
    const images = [
  {
    source: '../img/cdn/logos/jhm-logo.png',
    alt: 'Johns Hopkins Medicine official horizontal logo',
    figcaption: 'Johns Hopkins Medicine — Official Brand Mark'
  },
  // Add your new image entry here to match what is in /img/cdn/:
  {
    source: '../img/cdn/logos/jhm-crest.svg',
    alt: 'Johns Hopkins Medicine shield crest',
    figcaption: 'Official Johns Hopkins Medicine Academic Shield'
  }
];

Developer Safeguard: If an image file is placed in /img/cdn/ but has not yet been added to the images[] array in /js/site.js, the portal will still discover the image and display a yellow reminder note on the row (Note: Add this image to the images[] array in js/site.js) so you can spot missing metadata immediately during local testing.

4. Local Development Workflow (VS Code Live Server Required)

When working locally on your machine, you must run a local HTTP server (such as the VS Code Live Server extension) to test local /cdn/ folders:

  • Why VS Code Live Server is Required: Modern web browsers block JavaScript fetch() from scanning local hard drive folders when a file is opened directly via double-click (file:///C:/...). Opening the project with VS Code Live Server (http://127.0.0.1:5500 or http://localhost:5500) serves HTML directory listings that /js/site.js automatically crawls.
  • Automatic Local URLs: When running on localhost or 127.0.0.1, the portal automatically sets the Base URL to your local server address so clicking Copy URL, Generate Tag, or Open Raw File tests your local files directly before you upload them to Azure.
  • Source Switcher in the UI: Use the Source dropdown in the top toolbar to switch between:
    • Auto (Smart Detect) — Uses local folders on localhost, or Azure Live XML in production.
    • Azure Blob Live XML — Forces the UI (even on localhost) to query the live Azure container at jhmcdn.blob.core.windows.net.
    • Local /cdn/ Folders — Forces the UI to crawl local directories (requires VS Code Live Server).

5. Azure Blob Storage & CORS Configuration

For live Azure auto-discovery and cross-domain asset loading to work, the Azure Storage Account (jhmcdn) and container (global-assets) are configured as follows:

  • Container Public Access Level: Set the global-assets container access level to Container (anonymous read access for containers and blobs). This enables the public XML listing endpoint:
    https://jhmcdn.blob.core.windows.net/global-assets?restype=container&comp=list
  • Resource Sharing (CORS): Under the jhmcdn Storage Account → Settings → Resource sharing (CORS) → Blob service:
    • Allowed origins: *
    • Allowed methods: GET, HEAD, OPTIONS
    • Allowed headers / Exposed headers: *
    • Max age: 86400

6. How the 2-Tier Discovery Engine Works (/js/site.js)

Under the hood, /js/site.js uses a clean 2-tier discovery pipeline:

  1. Tier 1 — Azure Blob Live XML: Fetches ?restype=container&comp=list (with automatic <NextMarker> pagination support for large containers), parses each <Blob> node, extracts file size and last-modified date, filters for ^(css|js|img)/cdn/ paths via parseCdnAssetPath(), and joins image assets with the predefined images[] metadata array.
  2. Tier 2 — Local Dev Server Crawler: Recursively crawls directory links inside /css/cdn/, /js/cdn/, and /img/cdn/ when running on a local dev server (such as VS Code Live Server on localhost / 127.0.0.1).
